## 3. قواعد تسمية وتوليد الملفات

- **صيغة اسم الملف:** `DD-MM-YYYY_SessionType_TeacherName.md`
- **إدارة التكرار (Duplicate Handling):** عند إرسال تقرير جديد بنفس التاريخ والمعلم ونوع الحلقة، يُنشأ ملف مستقل بترقيم تسلسلي تلقائي `(1)`, `(2)` مع توثيق حالة التكرار صراحة في ترويسة YAML ومتن التقرير.
- **التحقق غير الإلغائي (Non-destructive Validation):** لا يُلغى حفظ التقرير أو تتوقف المنظومة عند نقص أي حقل، بل يُحفظ الملف بقيم بديلة احترازية (Fallbacks) مع وسم حالة التحقق (`MISSING DATA` أو `VALID`) وتوثيق قائمة الحقول الناقصة تفصيلاً.
- **مصدر التاريخ (Date Source):** يُوثق مصدر التاريخ بدقة (`FORM_INPUT` لتاريخ المعلم، أو `FALLBACK_SYSTEM_DATE` لتاريخ النظام البديل) لضمان دقة معالجة وكلاء الذكاء الاصطناعي لاحقاً.

## 4. سير العمل التشغيلي والتحديث (CLI Workflow)

المشروع مربوط ومُهيأ بالكامل محلياً عبر أداة Google الرسمية (`@google/clasp`).

### دفع التعديلات سحابياً:
عند تعديل أي ملف برمجي محلياً، يُنفّذ الأمر التالي لدفع التعديل فوراً إلى Google Apps Script:
```bash
clasp push -f
```

### سحب التعديلات من السحابة:
```bash
clasp pull
```

### فتح محرر السكربت في المتصفح:
```bash
clasp open
```

## 6. الفحص والاختبار (Testing)

ملف الاختبارات [`Test.js`](./Test.js) معزول ومخصص للمحاكاة:
- `testNormalSubmission`: اختبار دورة الإرسال القياسية والتحقق من سلامة البيانات والملفات.
- `testDuplicateSubmission`: اختبار الكشف عن التكرار والترقيم التسلسلي `(1)`.
- `testMissingFieldsPreservation`: اختبار حفظ التقرير مع نقص الحقول واستخدام القيم البديلة ووسم `MISSING DATA`.

## 7. سجل الأخطاء والتنبيهات (Error Logging)

1. **سجل الأخطاء الشهري:** تُسجَّل الإخفاقات تلقائياً داخل المجلد الرئيس في Google Drive باسم شهري مستقل: `automation_errors_YYYY_MM.log` لتفادي تضخم الملفات على المدى الطويل.
2. **التنبيهات البريدية:** عند حدوث أي خطأ قاتل، يُرسل إشعار بريدي فوري إلى مسؤول النظام يتضمن تفاصيل المعرف الزمني وتتبع الخطأ (Stack Trace).
